Preguntas para reflexionar¿Cuántos archivos tuvo que abrir para entender cómo se ve Section en cada versión? ¿Cuál le resultó más rápido de leer?Respuesta: En la versión CSS tuve que abrir dos archivos (Section.jsx y Section.css). En la versión Tailwind solo abrí un archivo (Section.jsx). Resultó mucho más rápido de leer la versión de Tailwind, ya que la estructura HTML/JSX y sus reglas visuales están juntas en un solo lugar.En su proyecto, ¿alguna vez cambió una clase CSS y se dañó otra parte de la página? ¿Por qué cree que pasó?Respuesta: Sí, suele suceder cuando se comparten nombres de clases genéricos (como .tarjeta o .titulo) en archivos CSS globales o sin encapsular. Al modificar una regla para un componente específico, esta afecta de forma no deseada a todos los elementos que usan la misma clase en otros archivos.¿Cuánto tiempo gasta inventando nombres de clases como .tarjeta-principal o .contenedor-2?Respuesta: Se pierde bastante tiempo definiendo nombres semánticos para cada contenedor o elemento, además de mantener la consistencia entre archivos.React divide la página en componentes. ¿Por qué tendría sentido que el estilo viva dentro del mismo componente?Respuesta: Porque React busca la modularidad y el encapsulamiento. Si un componente es una unidad independiente de lógica y estructura, tener su diseño en el mismo archivo facilita moverlo, reutilizarlo o eliminarlo sin dejar archivos o estilos "fantasma" en el proyecto.Mirando la clase p-6, ¿qué propiedad CSS cree que representa? ¿Y mb-3?Respuesta:p-6 representa la propiedad padding: 24px ($6 \times 4\text{px}$).mb-3 representa margin-bottom: 12px ($3 \times 4\text{px}$).¿Qué desventaja le ve a escribir muchas clases en el JSX?Respuesta: La principal desventaja es que la etiqueta HTML o componente se satura visualmente con muchas palabras, haciendo que el código JSX se vea más largo y denso a primera vista.4. Actividad de transferencia6.6 Cierre¿Qué beneficios se confirmaron en su proyecto?Respuesta: Se confirmó la velocidad para maquetar sin crear archivos extra, el aislamiento total de los estilos (evitando dañar otros componentes) y la facilidad para cambiar la paleta global de colores en un solo lugar (@theme).¿Qué preocupación resultó real y cómo la manejaron?Respuesta: La preocupación de que las líneas del JSX quedaran muy largas con múltiples clases. Se manejó ordenando las clases por categoría (ejemplo: primero diseño/layout, luego espaciados y finalmente colores/texto) o dividiendo elementos complejos en subcomponentes de React más pequeños.
